# Masked segmentation loss measurements — 2026-10-24

These synthetic measurements evaluate forward plus backward for all five losses. They compare
eager PyTorch, full-graph compiled PyTorch and the fused Triton backend. They do not measure
segmentation quality or end-to-end training speedups.

## Reproduction

Code: [d3ba67fbe8b24ec6b65bdc1f1fa3f813fcb6ad9c](https://github.com/rodolfo-viana/exacta/commit/d3ba67fbe8b24ec6b65bdc1f1fa3f813fcb6ad9c),
version `0.0.1a3.dev0`. Linux x86-64, Python 3.14.4, PyTorch 2.14.1+cu130,
Triton 3.8.0, NumPy 2.5.4; AMD Ryzen 9 5900XT, NVIDIA RTX 5070.
Each configuration ran separately, after the correctness tests finished. CPU timings use
16 threads, without CPU affinity. Ordinary desktop applications remained open.

Inputs use seed 0, softmax activation, index targets and float32 logits. For masked runs,
25% of labels are independently replaced with -100 and a boolean mask independently excludes
20% of voxels. Their intersection retains approximately 60%; the measured fraction is in the
tables. Inputs are identical across backends within each configuration. All remaining loss
parameters use defaults.

After installing that checkout, run the commands below. Each reports the median of 20 steps
after five warm-up steps; compilation is excluded. CUDA timing synchronizes each step.

```bash
OMP_NUM_THREADS=16 MKL_NUM_THREADS=16 python benchmarks/bench_losses.py \
  --classes 4 --sizes 128 --dtypes float32 --repeat 20 --warmup 5 --seed 0 --threads 16
OMP_NUM_THREADS=16 MKL_NUM_THREADS=16 python benchmarks/bench_losses.py \
  --classes 4 --sizes 128 --dtypes float32 --repeat 20 --warmup 5 --seed 0 --threads 16 \
  --ignore-fraction 0.25 --mask-fraction 0.2
OMP_NUM_THREADS=16 MKL_NUM_THREADS=16 python benchmarks/bench_losses.py \
  --device cpu --backends torch compiled --classes 4 --sizes 64 --dtypes float32 \
  --repeat 20 --warmup 5 --seed 0 --threads 16
OMP_NUM_THREADS=16 MKL_NUM_THREADS=16 python benchmarks/bench_losses.py \
  --device cpu --backends torch compiled --classes 4 --sizes 64 --dtypes float32 \
  --repeat 20 --warmup 5 --seed 0 --threads 16 --ignore-fraction 0.25 --mask-fraction 0.2
```

Additional GPU memory is peak allocation beyond the inputs, target, optional mask and logits'
gradient. A displayed 0.0 MiB does not mean no allocation: small scratch buffers can fit below
that baseline. CPU memory was not measured. No confidence intervals or repeated-seed timing
estimates were computed; clock frequency, allocation state and compilation choices can change
these results.

## Observations

For these inputs, fused Triton was the fastest tested GPU backend for every loss, with and
without exclusions. Masked Dice + CE took 1.071 ms, versus 3.719 ms for compiled PyTorch and
8.271 ms for eager PyTorch. Compiled PyTorch was the fastest tested CPU backend for every loss;
masked Dice + CE took 11.087 ms versus 23.432 ms eager. Different shapes, class counts, target
distributions and hardware need their own measurements.

## Correctness checks

The full CPU/GPU suite passed 2,606 tests with 8 skips. Five additional CPU full-graph compilation
checks passed on both PyTorch 2.14.1 and 2.4.1. The installed source distribution passed 1,096
tests with 620 skips under PyTorch 2.4.1+cpu and NumPy 1.26.4; that environment lacks CUDA and
several optional reference packages. Mypy and strict distribution metadata checks passed.

Masked values and gradients were compared against physically removing excluded observations.
Checks cover partial and entirely ignored cases, nonfinite excluded values, smaller integer
target dtypes, float64 finite differences, target gradients, mixed precision, noncontiguous
inputs and compilation. Reproduce the loss checks with:

```bash
OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 python -m pytest -q \
  tests/test_losses.py tests/test_weighted_losses.py tests/test_generalized_dice.py \
  tests/test_masked_losses.py
```
